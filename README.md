# 被禁言了我闭嘴 🤐

> 机器人在 QQ 群里被禁言(或群开了全员禁言)时,自动闭嘴,不再往那个群发任何消息;解禁后自动恢复。
> 防止"发不出消息还不停尝试"触发 QQ 风控。

## 这是什么?

QQ 机器人被群管理禁言后,如果 AI 还在不停地往群里发消息,QQ 会认为机器人异常,很容易触发**风控**(轻则消息发不出去,重则账号被限制甚至封禁)。群开**全员禁言**(比如夜间静音)时,普通成员身份的机器人同样发不出消息,道理一样。

这个插件就是干一件事:**机器人被哪个群禁言了,就自动对那个群闭嘴**;等解禁了,再自动恢复发言。全程自动,不需要你手动操作。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 🚫 自动闭嘴 | 机器人被群禁言后,立即拦截所有发往该群的消息 |
| 👥 全员禁言也闭嘴 | 群开全员禁言时同样拦截;机器人若是管理员/群主,会自动识别并放行(可关) |
| 🛡️ 拦截彻底 | AI 回复、其他插件的回复、定时推送……一条不漏(原理见下文) |
| ⏰ 自动恢复 | 收到解禁通知立即恢复;没收到也不怕,按禁言时长自动计时,到点恢复(发送时即时校验,不会多拦一秒) |
| 💾 重启/升级不丢 | 禁言状态保存在 `data/plugin_data/`,重启 AstrBot、升级插件都不丢 |
| 💰 省额度 | 禁言期间,那个群的消息不会触发 AI 回复,不白烧 token(可关闭) |
| 🔢 拦截计数 | 每个群拦了多少条,`/闭嘴状态` 一目了然 |
| 📋 管理命令 | `/闭嘴状态` 查看、`/闭嘴解除` 手动恢复、`/闭嘴` 手动闭嘴(兜底用) |

## 安装(二选一)

### 方式一:文件夹安装(推荐)

1. 把整个 `astrbot_plugin_shutup_when_muted` 文件夹,复制到 AstrBot 的 `data/plugins/` 目录下(没有就自己建);
2. 打开 AstrBot 的网页管理界面(WebUI);
3. 进入「插件管理」(或「插件市场」页),找到 **被禁言了我闭嘴**,点**启用**;
4. 完成。不需要配置任何东西。

### 方式二:压缩包安装

把插件文件夹压缩成 zip(注意:zip 里要能直接看到 `main.py`,不要多套一层文件夹),然后在 WebUI 插件管理里选择"安装本地插件 / 导入 zip"上传即可。

> 环境要求:AstrBot v4(>= 4.0.0),消息平台使用 **OneBot v11**(即 aiocqhttp 适配器)。
> 其他平台(如 Telegram、Discord)没有"禁言"概念,本插件不会生效,装了也无害。

## 使用

**不需要任何操作**,装上就自动工作。下面三个命令是给管理员留的兜底工具(建议**私聊**机器人发送):

| 命令 | 作用 |
| --- | --- |
| `/闭嘴状态` | 查看现在有哪些群被拦截、原因、还剩多久恢复、拦了多少条 |
| `/闭嘴解除 123456` | 手动解除群 123456 的拦截;不填群号则解除当前群 |
| `/闭嘴 123456` | 手动让机器人对群 123456 闭嘴(比如预感要被风控时主动闭嘴);不填群号则闭嘴当前群 |

> 注意:
> - 命令需要 AstrBot **管理员**权限;
> - 如果机器人在某个群里正被禁言,你在那个群里发 `/闭嘴状态`,它的回复也会被"闭嘴"拦下来(这是正常现象,说明插件在工作),所以查状态请去私聊;
> - 在群里发 `/闭嘴解除` 是可以成功的:命令执行时先解除拦截,再回复,回复就能正常发出去了。

## 配置(可选)

在 WebUI 插件配置页可以调三个开关,都有默认值,不调也能用:

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `block_on_whole_group_mute` | 开 | 群开全员禁言时也自动闭嘴。机器人是普通成员时确实发不出消息,建议开启;若机器人是群管理员/群主,插件会查询身份并自动放行(查询失败时按会被禁言处理,宁拦勿漏) |
| `skip_llm_when_muted` | 开 | 禁言期间,被禁言群的消息不再触发默认 AI 回复(避免生成发不出去的回复、浪费额度) |
| `log_blocked_sends` | 开 | 每次拦下一条消息都会写日志,方便你确认插件在工作;嫌日志吵可以关掉 |

## 它是怎么工作的?(原理,写给好奇的人)

1. **听通知**:OneBot 会在有人被禁言/解禁时推送 `group_ban` 通知。插件关心两种:`user_id`(被禁言的人)等于 `self_id`(机器人自己)的那条,以及 `user_id` 为 0 的那条(全员禁言/解除全员禁言),这时把群号记进"禁言名单";
2. **装安检门**:QQ 平台所有消息发送,最后都会经过 aiocqhttp 适配器的同一个出口方法(`AiocqhttpMessageEvent.send_message`)。插件在这里装了一道"安检门":目标群在禁言名单里,消息直接丢弃、不会真的发出去;
3. **自动恢复**:收到解禁通知就移除名单;同时每 30 秒检查一次,禁言时长(`duration`)到了也自动移除——就算解禁通知因为机器人掉线没收到,也能正常恢复。发送时也会即时校验到期时间,不会因为后台循环还没跑到而多拦;
4. **兜底**:名单保存在 `data/plugin_data/astrbot_plugin_shutup_when_muted/muted_groups.json`,重启不丢(从旧版本升级会自动迁移);万一状态不对,用 `/闭嘴解除` 手动恢复。

## 常见问题 (FAQ)

**Q: 怎么确认插件在工作?**
A: 两个办法。① 打开 AstrBot 日志,搜「被禁言了我闭嘴」,禁言时会看到"群 xxx 被禁言 N 秒,已拦截该群消息发送",每次拦下消息也会有记录;② 私聊发 `/闭嘴状态`,每个群后面会显示"已拦截 N 条"。

**Q: 我被禁言了,但插件没拦截?**
A: 检查三点:① 消息平台是不是 OneBot v11(aiocqhttp);② 插件有没有启用;③ 禁言通知里 `user_id` 是不是机器人自己的 QQ(如果协议端发的通知字段不全,可能判断不了,日志里会有提示)。

**Q: 群开了全员禁言,插件会闭嘴吗?**
A: 默认会(配置项 `block_on_whole_group_mute`)。如果机器人是这个群的管理员或群主,全员禁言不影响发言,插件会查询身份后自动放行;查询身份失败时会保守起见继续拦截。你的机器人是管理员、且希望全员禁言时也照常发言的话,把这个配置关掉即可。

**Q: 解禁了但机器人还在闭嘴?**
A: 大概率是没收到解禁通知。两个办法:① 等禁言时长走完(插件会自己恢复);② 私聊发 `/闭嘴解除 群号` 手动恢复。全员禁言没有时长概念,只能等解除全员禁言的通知,或者手动解除。

**Q: 会不会误伤其他群?**
A: 不会。名单是**按群**记录的,一个群被禁言只影响那个群,其他群正常发消息。

**Q: 插件把 AI 回复都拦了,会不会影响其他插件?**
A: 不影响其他插件工作,只是它们要发到被禁言群的消息会被拦下来(这本来就是目的)。个别插件如果绕过 AstrBot 的发送出口、直接调用协议端 API 发消息,不在拦截范围内(这种情况极少)。

**Q: 从 v1.0 升级,原来的状态会丢吗?**
A: 不会。升级后第一次启动会自动把旧状态迁移到新位置(`data/plugin_data/` 下),已到期的禁言会被顺手清理。
